# Tidal Echo · Frontend PWA Deployment Guide

The mobile side—once you **“Add to Home Screen,”** it becomes a standalone private chat app, communicating with your AI companion on your computer (Claude Code + channel plugin) through your own relay backend.

> This is a reusable frontend extracted from a private AI companion system and **fully sanitized**. No domains, keys, or private names are hardcoded in the code—names are configured through `CONFIG`, and the address uses a relative path + your nginx prefix.

Purely static: one `index.html` (with all CSS/JS included, no build step), one `sw.js`, one `manifest.webmanifest`, and several theme images. Drop it into nginx and it works.

---

## 0. Prerequisites

First, get the **backend** running (see `../backend/DEPLOY.md`): the relay should respond at `https://your-domain/relay`, and the smoke tests should pass. The frontend is simply its client.

> **HTTPS is required**: PWA installation, Service Worker, and Web Push all require https.

---

## 1. Deploy the files

Deploy the entire `web/` directory to the static directory pointed to by nginx, for example `/var/www/companion-web/`:

```bash
rsync -av web/  root@your-VPS:/var/www/companion-web/
```

nginx mounts it at `/chat/` (see `location /chat/` in `../backend/nginx-companion.conf.example`). Changes to static files **take effect immediately without restarting**.

Public URL: `https://your-domain/chat/` → open it in your phone's browser → Share menu → “Add to Home Screen”.

---

## 2. Configuration (only one place to change)

Open `index.html`. At the top `<script>` there is the **only configuration block**:

```js
const CONFIG = {
  APP_NAME:   "Tidal Echo",  // App / menu title (also change it in the manifest, see below)
  AI_NAME:    "Claude",       // Display name of your AI companion (top bar / calls / notifications / narration)
  HUMAN_NAME: "You",          // How to refer to you in narration (rarely shown)
  SINCE:      "2026/01/01",   // Starting date for "days together" on the menu page, YYYY/MM/DD (leave "" to hide the counter)
};
```

* `AI_NAME` is recommended to match the backend's `RELAY_AI_NAME` in `relay.env` (the notification title is generated by the backend using that name).
* Users can still change the displayed name locally on the “Profile” page; it is stored on the device and does not affect anyone else.
* To change the App name: also change `name` / `short_name` in `manifest.webmanifest`, and `AI_NAME` at the top of `sw.js` (fallback notification title).

**Path**: `const API_BASE = "/relay"` — same-origin relative path, corresponding to the backend's `RELAY_PUBLIC_PREFIX`. If you mount the API under a different prefix, change it here (do not hardcode the domain).

**Avatar / icons**: `avatar-sea.png` is the default avatar (abstract ocean surface; users can change it in the App); `icon-192/512.png`, `apple-touch-icon.png`, and `favicon.png` are placeholder “tide” icons. Replace them with your own files using the same filenames.

## 3. Contract with the backend (new frontends must match these)

| Direction / Event         | Convention                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Message direction         | `from: "human" \| "ai"` (human / AI)                                                                                         |
| Poke event                | `{ type:"reaction", id, reactions:{ai:"❤️"}, by:"ai" }`                                                                      |
| API base                  | `/relay/` (backend `RELAY_PUBLIC_PREFIX`)                                                                                    |
| PWA static files          | `/chat/` (backend `RELAY_APP_PATH`; notification clicks return here)                                                         |
| History / realtime / send | `GET /app/history` · `SSE /app/stream` · `POST /app/send`                                                                    |
| Online heartbeat          | `POST /app/ping` (every 60s while the app is in the foreground)                                                              |
| Push notifications        | Public key `GET /app/vapid_public` · subscriptions `POST /app/subscribe` / `/app/unsubscribe`                                |
| Voice / calls / TTS       | `POST /app/voice` · `/app/call` · `/app/tts` (automatically falls back if the backend is not configured)                     |
| Authentication            | Every request includes `Authorization: Bearer <RELAY_SECRET>`; SSE uses `?token=` (browser `EventSource` cannot set headers) |

The “Connection Key” entered on the login page = backend `RELAY_SECRET`, stored in the browser's local `localStorage` (all keys start with `companion_`).

## 4. Themes

Two themes, stored in `localStorage.companion_theme`, selectable under “Profile → Theme”:

* **Pearl** (`light`, default) — warm white pearl tide
* **Harbor** (`harbor`) — neutral cool tones, suitable as a base for further color customization

To add a new theme: copy a section like `:root[data-theme="harbor"]{…}` inside `<style>`, add an entry to `THEMES` / `WALLS`, add a button in the menu, and provide a `chat-xxx.webp` + `menu-xxx.webp` wallpaper.

---

## 5. Service Worker / caching (**read this before modifying the frontend**)

At the top of `sw.js`:

```js
const CACHE = "companion-v1";   // ← bump this every time you modify the frontend (v1 → v2 → …)
```

* Strategy: navigation requests use **network-first** (an online refresh gets the latest `index.html`); other same-origin GET requests use **cache-first**; `/relay/` is never intercepted.
* **If you don't bump the version number, users who have already added the app to their Home Screen may remain on the old shell indefinitely** (the old `index.html` is precached). Bump the version → the SW reinstalls → precaches again → activates → removes the old cache.
* Verification: refresh once while online to get the new version (the SW updates in the background); occasionally, you may need to refresh a second time for the SW to fully switch over.

---

## 6. Lock-screen push notifications (optional)

After configuring VAPID on the backend (see `../backend/DEPLOY.md` §4), enable it under “Profile → Lock-screen notifications”:

* On iOS, push notifications only work inside a standalone PWA added to the Home Screen; they do not work in a regular Safari tab (the App already displays a notice about this).
* Logic: only when the PWA is **not in the foreground** will an AI reply trigger a lock-screen notification; when the app is open in the foreground, it won't disturb you.

---

## 7. Placeholders / intentionally empty features

To match the “core chat” backend, the following are **placeholder buttons**. Clicking them only shows a toast or example data; they are not connected to the backend. They are kept so you can use them as a reference when connecting your own features:

* Menu page: Movie / Memory / Tides / Room
* Settings page: model selection / effort / context threshold / reset / swap / status (displays example numbers)
* **Album** `album.html`: complete album UI shell. The file header specifies the `/relay/app/album/*` endpoints you need to implement yourself; without a backend connection, it displays a key gate / empty state.

Core chat features (text / images / voice / calls / poke / push notifications) are connected to the backend.

---

## 8. Security

* Do not commit a populated key, your domain, or real avatars/icons to a public repository.
* `companion_secret` is stored in the user's browser locally; it is equivalent to the backend's `RELAY_SECRET`. If it is leaked, someone can read your entire conversation history. This is a single-user model where one key represents **you and your AI**.
